## 1. 项目概述

### 1.1 目标

开发一款**轻量级、跨平台、TUI 界面**的 SSH / SFTP 连接管理工具，对标 Xshell / SecureCRT 的核心体验，但具备两个差异化特征：

1. **纯 Rust 实现、单二进制、零运行时依赖**——可直接丢到任意机器上运行，不需要安装 OpenSSL、libssh2 或系统 SSH 客户端。
2. **原生为 AI 设计的操作接口**——所有能力（开会话、执行命令、读屏、传文件、查日志）都以结构化子命令暴露，AI Agent 通过命令行即可像人一样操作远程主机，并受内置风险分级引擎约束。

### 1.2 定位边界

- 它**不是**终端模拟器替代品：不提供本地 shell，只承担"连接到远端并管理这些连接"的职责。
- 它**不是** Ansible：批量执行是轻量级的"广播 + 汇总"，不做声明式配置收敛。
- 它**是**一个「会话中心」：所有远程会话集中在一个常驻进程里，TUI 与 AI 共享同一批会话与同一份审计日志。

### 1.3 与 Xshell 的关键差异

| 维度 | Xshell | sh0 |
| --- | --- | --- |
| 界面 | GUI | TUI（ratatui），可跑在纯命令行服务器/跳板机上 |
| 形态 | 单体 GUI 应用 | 常驻 daemon + 多前端（TUI / AI CLI / 未来的 MCP） |
| 自动化 | VB/JS 脚本 | 结构化子命令，面向 AI Agent 设计 |
| 跨平台 | Windows 为主 | Linux / macOS / Windows 全平台 |
| 依赖 | 安装包 | 单文件二进制 |

## 2. 术语表

| 术语 | 含义 |
| --- | --- |
| Host | 一台远程主机的连接配置（地址、端口、用户、认证引用、分组、标签） |
| Credential | 认证凭据实体（密码 / 私钥 / agent / keyboard-interactive / 2FA） |
| Session | 一条活跃的 SSH 连接及其终端状态（PTY channel + 屏幕网格 + 滚动缓冲） |
| Screen / Grid | 本地维护的终端字符网格，由远端字节流经 xterm 解析器还原 |
| Scrollback | 滚出屏幕的历史行缓冲 |
| Broadcast | 将同一段输入同时发送到多个已选会话 |
| Batch | 对一组主机并行执行同一命令并汇总结果 |
| Risk Level | 命令风险等级：`auto` / `confirm` / `deny` |
| Actor | 动作发起者：`user`（人类键鼠操作）或 `ai`（AI 子命令调用） |
| Daemon | 持有全部会话的常驻后端进程 |

## 3. 用户与场景

### 3.1 目标用户

- **运维 / 后端工程师**：日常需要同时维护 5~50 台主机，习惯键盘操作。
- **AI Agent / 自动化流水线**：需要在远程主机上"看一眼、跑一条命令、取一个文件"，但必须可控可审计。
- **混合使用者**：人开着 TUI 排查问题，同时让 AI 在同一批会话上取数、传文件。

### 3.2 典型场景

| 编号 | 场景 | 描述 |
| --- | --- | --- |
| SC-1 | 快速连机 | 从主机树双击/回车即连，常用主机支持模糊搜索直达 |
| SC-2 | 多会话并行 | 顶栏标签在 10+ 会话间切换，支持广播输入 |
| SC-3 | 断网自愈 | 网络闪断后自动重连，重连前的输出不丢失 |
| SC-4 | AI 排查 | AI 调用 `sh0 ai exec` 在多台机器上跑诊断命令并取回结构化结果 |
| SC-5 | AI 交互 | AI 读到 `vim` 界面卡住时，用 `screen read` 看屏、`input send` 注入按键脱困 |
| SC-6 | 文件搬运 | TUI 双栏拖拽式上传下载；AI 用 `file upload/download` 做批量分发 |
| SC-7 | 批量巡检 | 对 30 台主机并行跑 `df -h`，结果以表格汇总，异常行高亮 |
| SC-8 | 事后审计 | 查询"上周 AI 在 web-01 上执行过哪些危险命令" |

### FR-7 权限与风险分级

> **M2 已实现**：FR-7.1 ~ FR-7.7 全部。判定链路为「全局 deny 正则 → 分段 deny → 用户规则 →
> confirm → auto 白名单 → 默认档（Confirm，宁拦勿放）」，支持 `sudo/env/timeout` 包装剥离与
> 主机 `risk_cap` 压制；用户可在 `risk.toml` 增删规则；单 actor 每分钟调用数可限。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-7.1 | 三档风险分级引擎：`auto`（自动执行）/ `confirm`（需确认）/ `deny`（直接拒绝） | P0 |
| FR-7.2 | 判定输入：命令字符串经 shell 词法切分后的程序名 + 参数 + 危险模式正则 | P0 |
| FR-7.3 | `deny` 内置黑名单：`rm -rf /`、`mkfs*`、`dd of=/dev/*`、`shutdown/reboot`、fork 炸弹、`curl|sh`、覆写 `authorized_keys`/`sshd_config`、清空 `iptables` 等 | P0 |
| FR-7.4 | `confirm` 档：AI 调用时在 TUI 弹出确认框（有人值守）或返回 `needs_confirmation` 错误码并给出确认令牌（无人值守，AI 需二次调用带令牌） | P0 |
| FR-7.5 | 规则可配置：用户可在 TOML 中增删规则、调整命令所属档位 | P1 |
| FR-7.6 | 按主机/分组设置风险上限（如生产组禁用 `auto` 档） | P1 |
| FR-7.7 | 速率限制：单 actor 每分钟命令数上限，防止 AI 失控 | P1 |

## 6. 约束与假设

1. **远端 PTY 由服务端提供**：本地不需创建 PTY，因此 Windows 端不存在 ConPTY 适配负担——这是选 TUI 而非内嵌本地 shell 的直接收益。
2. 远端主机需开启 `pty` 与（SFTP 场景）`subsystem sftp`。
3. 目标环境默认提供 UTF-8 locale；非 UTF-8 远端按 GBK/拉丁系回退解码（可配）。
4. `russh` 算法覆盖面略窄于 OpenSSH：老旧设备（ssh-dss、部分 CBC cipher）可能连不上，需提供"算法放宽"开关并给出明确报错。
5. 首版不实现 SSH 服务端功能，仅客户端。

## 7. 明确不做（Out of Scope）

- 本地 shell / 本地终端模拟（交给用户自己的终端）
- GUI 版本（Electron / Tauri / egui 均不做）
- 声明式配置管理、Playbook、幂等收敛（Ansible 的活）
- SSH 证书颁发机构（CA）管理
- 多用户协作、云端同步主机列表
- 内嵌文本编辑器（远程编辑走外部编辑器）
